## Decided for review

Decisions an autonomous run made on the user's behalf: question, options, choice, why, where in the code. The user reviews them; they never block a run.

- **Stage A · A3 — starting the primary session again re-offers the task's prompt.** A2 left it to the caller whether a start that finds no conversation to resume hands the prompt over again. Choice: yes, for the task's primary session only, decided on the server (`SessionService` → `#taskPrompt`, design.md **Sessions**), because the prompt is the task's work and only a launch that never reached the agent gets it — a real resume still drops it. This covers a user restart and a restore after a server restart (a review finding: the restore used to lose the prompt and leave the session marked running without it). The session row a failed create leaves behind (`stopped` with its `launchError`) is what makes the user restart recoverable. Tests: `tasks-rpc.test.ts`, both directions with the fake claude agent.
- **Stage A · A3 — a failed primary launch keeps the task, and `tasks.create` still succeeds.** Options: roll the task back, fail the call and keep the task, or return the task with the session stopped. Choice: return the task; the primary session row exists in `stopped` with `launchError`, which the stopped-session pane already shows with a Start again button, so a stale profile or a missing CLI costs the user no typing. `CreateTaskInput.agent.kind` is `AgentKind`, not `SessionKind`, so `create` can never ask for a shell and `ShellPromptError` stays unreachable from `tasks.create` (no RPC mapping was needed for it).

- **Stage A · A0 — per-project settings cover the paths the config names.** A `[projects."<path>"]` table resolves for exactly that repository (canonicalized with `realpathSync` when it exists); a project added only in the app uses the global `[tasks]` values. Why: resolution stays a property of the file the user edits, so adding or removing a project never has to re-push config, and Settings can show every override together with where it came from. A repository or symlink that appears after the file was read picks its table up on the next save (documented in `docs/agent-profiles.md`). Code: `apps/server/src/config/config-file.ts`, `packages/protocol/src/config.ts`.
- **Stage A · A0 — a table `agent` that contradicts the profile beside it is reported and dropped**, never silently ignored, so Settings and the composer cannot advertise a launch `launchSnapshotFor` would refuse. The profile's agent decides the model check. Same rule for `[tasks]`, `[naming]` and every project table. Code: `config-file.ts` (`agentKeepingProfile`, `launchConsistentSettings`).
- **Stage A · A0 — `worktree-root` validation and `~` expansion live in the server** (`apps/server/src/config/worktree-root.ts`) because `packages/protocol` has no node types; absolute means `node:path` `isAbsolute`, so Windows drive paths work. The Windows-only case is a platform-gated test that skips on this Linux machine.
- **Stage A · A1 — two projects with the same directory name share `<root>/<repo>/`** and are told apart by the `-2`, `-3` suffixes on their slugs; the branch prefix is normalized to exactly one trailing `/`; an explicit branch gets the same ancestor/descendant conflict check as a derived one (`a branch named 'corral' blocks 'corral/fix'`). Recorded in `docs/design.md` next to the worktree path; code in `apps/server/src/tasks/worktree-plan.ts`, `apps/server/src/git/names.ts`.
- **Stage A · A2 — the prompt argv is shaped per agent, not by a shared rule.** Claude gets one leading space (its commander dispatches a subcommand on the first operand even after `--`), Codex always gets `--` (clap honors it), pi gets a leading space only for `@`-leading text (pi reads `@path` as a file even after `--`), OpenCode attaches a dash-leading prompt to `--prompt=`. Without this, a prompt whose first word is `review`, `mcp` or `update` would run a subcommand. A shell session rejects a prompt. Code: the four adapters under `apps/server/src/agents/`.
- **Stage A · A4 — OpenCode is refused as a `[naming]` runner** with a config problem, because 2.2.5's `run` has no ephemeral/no-session flag and would leave sessions behind; **Codex naming runs read-only with the user's config and rules ignored** (`--ignore-user-config --ignore-rules -s read-only -c approval_policy=never`), which cannot write but can still read what the server user can read — stated in the adapter and `docs/agent-profiles.md` instead of claiming no-tools. Naming failures and timeouts keep the seed title and log only the reason, with no retry.
- **Stage A · A5 — the composer keeps its draft across a project switch made in the sidebar and across a failed create**; Escape is refused while an attempt failed, with a muted line that names the way out. The 46 rem lane is a kit `ContentLane` variant because the AST class gate forbids arbitrary widths in modules. Code: `apps/web/src/modules/tasks/new-task-view.tsx`, `new-task-draft.ts`.
- **Stage A · A6 — an imported issue title is stored with `titleSource = "user"`**, per the A3 plan rule ("the user saw and accepted it"), so naming never rewrites it; new default bindings take over a chord the file configures (the file entry is dropped and Settings reports the conflict — documented in `docs/ux.md`).
- **Stage A · A7 — inside the Done section, done-but-seen and idle tasks sort by recency** (as `layout.md` says) rather than always done-before-idle; flat mode lists no other task's sessions, which A8 then made moot by moving sessions to tabs.
- **Stage A · A8 — the session strip is a named structural variant on the stock `Button` with ARIA `tablist`/`tab` roles, not Base UI Tabs**: a kit `TabsTrigger` cannot host the sibling stop/menu/close controls and `layout.md` asks for content-width tabs, not the kit's equal-width triggers. Documented in `docs/ui-kit.md`. The three status colour tokens are the one theme addition, also recorded there. The browser suite now runs at the app's 1024×640 minimum instead of Vitest's 414×896 default.
- **Stage A · run — the release is protocol 8.** Version 6 carried the settings and rename additions, 7 the task prompt and `seenAt`, 8 `toggle-sidebar`; none of them is released, so a daemon at 6, 7 or a v5 daemon is refused at the handshake (the barrier keeps working, the number is not a claim about releases).

## Known risks and verification limits

- **Multi-client terminal sizing (found by A-verify, outside the 11 steps, P2).** With two clients attached to the same terminal at different window sizes (desktop app plus a browser window, or two browser windows), each client adopts the grid of whichever client last fitted, so the other shows the terminal clipped or letterboxed until its own window is resized by a pixel; the PTY keeps working. It predates stage A (the fit and stream code is older) and is not part of the stage A scenario, so it did not change the verdict. Not fixed in this run: a correct fix is either a protocol change (a per-client view of one PTY grid) or a deliberate refit-on-focus policy, and both are wider than the stage. Repro and evidence: `.e2e/stage-a/verify/report.md` **Issues**, `evidence/19-multi-client-size.json`, `screenshots/29-*`, `screenshots/30-*`.

- Baseline font-control gap (confirmed in parent review): font-size +/-/reset exists in playtest but is absent in Corral, whose terminal text is fixed at 14px. The shadcn migration neither introduced nor fixes this gap; no font controls are implemented in this scope.
- Two first-character drops after Rename were recorded with the dialog detached and terminal focused. Later controlled and instrumented repeats were intact; neither a harness cause nor an app-side root cause is proven. Do not label this resolved or dismiss it as a transient. Evidence: UI worktree `.e2e/graphical-workspace/verify/forensic-a0/report.md`; source trace confirms stable terminal-id/effect dependencies and no asynchronous snapshot-to-input-listener gate. Final verification added 36 intact Rename→input checks with first-key focus/modifier evidence; this is not a fix or an explanation of the earlier drops. A recurrence needs per-key focus/modifier, client terminal-frame and PTY-input timing (the latter remains uncaptured).
- Long profile rows may truncate in the stock picker; full values remain in accessible names and the effective summary (P3). At 1024×640, New task requires inner scrolling to reach Create/Cancel; browser and Electron usability verified. No launch/selection failure observed.
- Verification uses real PTYs/git/SQLite/sockets with fake paid agent executables. Actual paid provider calls and native OS spawn failures are not verified.
- Final sentinel scan saved its result and exported rows/logs, but not the raw 11 RPC frames or temporary SQLite files. See the evidence caveat in `.e2e/final-combined/report.md`.
- Client-state inspection found that a failed watch can leave `watching` set while the control socket stays connected; per-watch error/retry is not exposed. This is a source-level risk, not a reproduced incident or a completed fix. Architecture changes remain a separate user decision (`research/client-state.md`).
